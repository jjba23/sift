The two configuration files, the four layers in which they are read, and the
single knob that is not a setting.  Configuration is data throughout: a
configuration file cannot execute anything.

* Configuration
:PROPERTIES:
:CUSTOM_ID: configuration
:END:

A ~file-filter~ determines what a *directory* denotes when sift walks it: ~*~
does not cross a path separator, ~**~ does, a leading ~!~ negates a pattern,
and the last pattern that matches a file decides.  A file named on the command
line is always read: the filter constrains the walk, not the arguments.

Four layers, each taking precedence over the one before it: built-in defaults,
the system file (~/etc/sift/config.yaml~), the user file
(~$XDG_CONFIG_HOME/sift/~), the project file, and finally the command line.
Discovery ascends from the current directory and stops at the repository root,
so a file in a home directory cannot silently apply to an unrelated checkout.

Two formats share one schema.  YAML is data, read and validated, and it cannot
execute anything, which makes it the format to keep under version control.

#+begin_src yaml
dialect: elisp
style: community
line-length: 90
brackets: square
blank-lines: one
single-letter-names: [i, j, k]
field-macros: [package, operating-system, my-record]
file-filter: ["src/**", "!src/generated/**"]
max-positional: 4
inlay-hints: [parameters, types]
stdlib: true
severity: warning
checkers:
  - trailing-whitespace
  - docstring-missing
exclude-checkers: [line-length]
indent-rules:
  - [with-my-thing, 2]
#+end_src

Scheme is code, and is loaded only when it is trusted: named with ~--config~,
permitted for a single run with ~SIFT_TRUST_CONFIG=1~, or recorded once with
~sift config trust sift.scm~, which adds the project to
~$HOME/.config/sift/trusted-projects~.  A repository that is cloned and then
opened must not be able to run code merely because sift was pointed at it.

#+begin_src scheme
;; sift.scm
`((dialect . scheme)
  (line-length . 90)
  (indent-rules . ((with-my-thing . 2))))
#+end_src

A malformed configuration is an error, reported with a position:

#+begin_example
sift: sift.yaml:1:1: unknown configuration key `line-lenght'
#+end_example

The language server is configured from these same files, so a project's
~sift.yaml~ is the single place where its editor behaviour is written down:
~inlay-hints~ (which kinds of hint, or none), ~hover~ and ~completion~
determine what the server answers, and ~stdlib~ decides what it reads for the
names the project does not define -- ~true~ for the library this machine has
installed, including the third-party packages installed beside it, ~false~ for
none, and a list of directories and source URLs to read instead.
~download-sources~ allows the URLs in that list to be fetched; it is false by
default, because reaching the network is a decision a project file should not
make on its own.  ~compiler-diagnostics~ asks the dialect's own compiler for a
second opinion when a buffer is opened or saved; ~optimize-imports~ and
~sort-imports~ decide what "organize imports" means and are both on by default:

#+begin_src yaml
stdlib: false                      # the project is the whole answer
stdlib: [/opt/guile-src/module]    # a source tree unpacked somewhere
#+end_src

An archive is named by URL, and fetched only when the network is allowed:

#+begin_src yaml
download-sources: true
stdlib:
  - https://example.org/guile-3.0.11.tar.gz
  - /opt/local/sources
#+end_src

An editor may send its own settings as
well -- Eglot's ~eglot-workspace-configuration~, a ~settings.json~ section,
~initializationOptions~ -- and these are layered over the files and validated
in the same way, with a key that sift does not define reported in the
editor's log rather than silently ignored.  [[file:editors.org][editors.org]] gives the object
each editor sends.

A typo that is silently ignored is indistinguishable from a setting in
effect, so an unknown key is refused and named.  Which layer won is likewise
never in doubt:

#+begin_src shell
$ sift config show --verbose
dialect: elisp   # /home/joe/project/sift.yaml
style: community   # /home/joe/project/sift.yaml
line-length: false   # default
indent: 4   # command line (--indent)

$ sift config explain line-length
line-length
  Soft line limit; #f means 96, or 80 for Emacs Lisp.
  type:    integer
  default: #f
  flag:    --line-length
#+end_src

The complete list of keys, with their defaults and the flags that override
them, is what ~sift config show~ prints, and every key is documented by
~sift config explain KEY~.  The Emacs package carries its own settings, listed
in [[file:emacs.org::#emacs-settings][doc/emacs.org]].

* Running sift in parallel
:PROPERTIES:
:CUSTOM_ID: parallel
:END:

A run over a project is a sequence of independent runs, one per file: nothing
a checker reads in one file is anything it reads in another.  ~lint~,
~format~, ~check~ and ~ci~ therefore spread the files over the processors.
Results are collected in file order and printed in file order, so a parallel
run emits exactly the bytes a sequential run emits; only the wall clock
differs.

No configuration is required.  ~SIFT_JOBS~ is the sole knob, and it exists to
keep a parallel run comparable with a sequential one:

#+begin_src shell
SIFT_JOBS=1 sift ci .    # one thread, same bytes: for profiling, and for
                         # checking that a difference in the output is a bug
SIFT_JOBS=4 sift ci .    # four workers, on a machine that has twelve
#+end_src

Two runs are never parallel: ~format --write~ and ~lint --fix~, which write the
files they read.  Such a run stops at the first file it cannot read, rather
than half-rewriting a tree and then reporting it.

* The settings a project is likely to change
:PROPERTIES:
:CUSTOM_ID: settings
:END:

Every decision recorded in [[file:style.org][the style]] is a default.  The ones a project
is likely to hold differently are settings rather than arguments to be had in
an issue thread:

| Setting               | Values                        | The default            |
|-----------------------+-------------------------------+------------------------|
| ~style~               | ~community~, ~dangling~       | ~community~            |
| ~brackets~            | ~square~, ~parens~, ~preserve~ | ~square~ in Scheme    |
| ~blank-lines~         | ~preserve~, ~one~             | ~preserve~             |
| ~line-length~         | a number                      | 96 (80 for Emacs Lisp) |
| ~indent~              | a number                      | 2                      |
| ~comment-align~       | ~#t~, ~#f~                    | ~#f~                   |
| ~single-letter-names~ | a list, for index variables   | ~(i j)~                |
| ~loop-keywords~       | ~literal~, ~symbolic~         | silent                 |
| ~indent-rules~        | a list of ~[name, columns]~   | the built-in table     |
| ~stdlib~              | ~true~, ~false~, directories  | ~true~                 |
| ~compiler-diagnostics~ | ~true~, ~false~              | ~true~                 |
| ~download-sources~    | ~true~, ~false~               | ~false~                |
| ~optimize-imports~    | ~true~, ~false~               | ~true~                 |
| ~sort-imports~        | ~true~, ~false~               | ~true~                 |

A project that has settled a convention should not have to fight its
formatter, and a formatter that has settled one should not have to argue;
this is why these values are data in ~sift.yaml~ and not opinions in the code.
