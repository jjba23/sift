The commands sift provides, the options each of them accepts, and the exit
statuses the program returns.  The README is the introduction; this page is
the reference.

* The commands
:PROPERTIES:
:CUSTOM_ID: cli
:END:

#+begin_src text
sift format         [OPTIONS] [FILE...]
sift lint           [OPTIONS] [FILE...]
sift check          [OPTIONS] [FILE...]
sift fix            [OPTIONS] [FILE...]     # lint --fix
sift ci             [OPTIONS] [FILE...]     # check + lint, for pipelines
sift lsp                                    # a language server on stdin/stdout
sift list-checkers  [--dialect DIALECT]
sift explain        CHECKER-NAME
sift config         show | explain | trust
sift install-hooks  [--force]
sift doctor
sift version
#+end_src

~sift --help~ prints a synopsis of the same commands, so the program states
its own interface.

Given neither a file argument nor ~--stdin~, ~format~, ~lint~ and ~check~
read standard input, in the manner of a filter.  With ~--stdin~, at most one
file may be named, and it is the *name of the source*: the dialect is detected
from it when the text itself does not say, and diagnostics name it rather than
~<stdin>~.  That is how an editor lints an unsaved buffer, and how a formatter
plugin such as [[https://dprint.dev/][dprint]]'s passes a file it has read.  A
directory argument denotes the set of every Lisp file below it, in sorted order,
so ~sift ci .~ applies the pipeline to the tree.

** Options
:PROPERTIES:
:CUSTOM_ID: options
:END:

The table is exhaustive, since an option absent from the reference is an
option nobody looks up.  Every option also has a configuration-file
counterpart, over which the command line takes precedence.

| Option                     | Where                           | What it does                                                          |
|----------------------------+---------------------------------+-----------------------------------------------------------------------|
| ~--dialect~                | all                             | Scheme, racket, elisp or cl; overrides detection                      |
| ~--stdin~                  | format, lint, check, ci         | Read one source from standard input                                   |
| ~--stdout~                 | format                          | Write the result to standard output (the default without ~--write~)   |
| ~--write~, ~-w~            | format                          | Rewrite the files in place                                            |
| ~--check~, ~-c~            | format                          | Ask the check question instead: write nothing, exit 1 on a difference |
| ~--diff~                   | format                          | Print the change as a unified diff, exit 1 when there is one          |
| ~--sort~, ~--alphabetical-sort~ | format                     | Sort top-level definitions by name; requires ~--write~               |
| ~--fix~                    | lint                            | Apply the fixes the rules have, then organize imports (unused removed, specs sorted) |
| ~--checker NAME[,NAME...]~ | lint                            | Run only these rules                                                  |
| ~--exclude-checker NAME~   | lint                            | Skip these rules (repeatable)                                         |
| ~--severity~               | lint, lsp                       | error, warning or info; the smallest one to report (default ~info~)   |
| ~--format~                 | lint, check, ci                 | human, json, null, github or sarif (default ~human~)                  |
| ~--style~                  | format                          | community (trailing closers) or dangling (own line)                   |
| ~--brackets~               | format                          | square, parens or preserve, for clause lists                          |
| ~--blank-lines~            | format                          | preserve, or one blank line between top-level forms                   |
| ~--line-length N~          | format, lint                    | Soft line limit (96, or 80 for Emacs Lisp)                            |
| ~--indent N~               | format                          | Indentation width (default 2)                                         |
| ~--comment-align~          | format                          | Line up contiguous inline comments                                    |
| ~--file-filter~, ~-p~      | format, lint, check, ci         | Only read files matching these globs when walking a directory         |
| ~--no-color~               | all                             | No ANSI colour (also honours ~NO_COLOR~ and a non-tty stdout)         |
| ~--quiet~, ~-q~            | lint, ci                        | Drop the summary line                                                 |
| ~--verbose~, ~-v~          | all                             | Say what is being processed                                           |
| ~--force~                  | format, lint, ci, install-hooks | Format or fix a file that has parse errors; replace an existing hook  |
| ~--label NAME~             | format, lint, check             | Name the stdin source; its name picks the dialect and is what diagnostics say |
| ~--config FILE~            | all                             | Read this configuration file instead of discovering one               |
| ~--trust-config~           | all                             | Allow this project's Scheme configuration to be evaluated             |
| ~--watch~                  | format, lint, check, fix, ci    | Run again whenever the files the run read change, until interrupted   |
| ~--~                       | all                             | Stop option parsing; everything after it is a file                    |

A long option may be abbreviated to any prefix that is unambiguous: ~--dial
elisp~ denotes ~--dialect elisp~, and both ~--dialect elisp~ and
~--dialect=elisp~ are accepted.

** Watching
:PROPERTIES:
:CUSTOM_ID: watch
:END:

~--watch~ turns a run into a loop: the command runs once, and again every time
a file it read changes, until the process is interrupted.

#+begin_src shell
sift lint --watch src/          # re-lint the tree on every save
sift ci --watch .               # the pipeline's two questions, in a loop
sift format --write --watch .   # format on save, from the other side
#+end_src

It watches what the run *read* rather than the operands it was given, so
~sift ci --watch .~ notices a file created three directories down, and a
project's ~file-filter~ is the filter the watch uses because it is the filter
the run used. Each look is a ~stat~ per file, half a second apart: there is no
inotify here and nothing to install, so it works the same on Linux, macOS and
anywhere a POSIX file system answers.

The watcher writes its own lines to standard error -- which file changed, how
many are watched -- and leaves standard output to the command, so
~--format=json~ stays one document per run.  A run that changes the files it
reads, like ~format --write~, does not trigger itself: the timestamps are read
after the run, not before it.

Three things are refused rather than silently ignored: ~--watch~ on a command
that reads no files (~version~, ~explain~, ~lsp~), ~--watch~ with ~--stdin~
(standard input is read once), and ~--watch~ with no file or directory to
watch.  The exit status is not used once watching: a finding is something to
look at rather than a reason to stop, and Ctrl-C ends the loop.

** Exit codes
:PROPERTIES:
:CUSTOM_ID: exit-codes
:END:

| Code | When                                                                     |
|------+--------------------------------------------------------------------------|
| 0    | everything is clean at the severity you asked for                        |
| 1    | findings at or above that severity, or a file that ~format~ would change |
| 2    | a usage error, an unreadable file, or a file that cannot be parsed       |

A usage error is an unknown dialect, an unknown rule named in ~--checker~, a
malformed value, ~--write~ combined with ~--stdout~, or ~ci~ combined with
~--fix~.  A file with an unbalanced delimiter is *recoverable*: ~lint~ reports
it as a finding (status 1), whereas ~format~ and ~fix~ refuse to write
(status 2) unless ~--force~ is given, in which case the balanced prefix is
formatted and the unbalanced tail is copied unchanged.
